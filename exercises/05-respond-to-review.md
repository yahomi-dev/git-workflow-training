# quest-05: 差し戻しに対応する

<!-- quest:start -->
## 状況

図書室の担当者から: 「開館時間の表の下に、入館についての注記を 1 行足してください。文言は『入館は閉館の少し前までにお願いします。』で。」

今回は進行役が **一度差し戻し** ます。差し戻されてから、マージまでの往復を通します。

## やること

1. ブランチを切る

   ```bash
   git switch main
   git pull
   git switch -c quest/05-entry-note
   ```

2. `site/index.html` の開館時間の `</table>` の直後に 1 行足す

   ```html
   <p class="hours-note">入館は閉館の少し前までにお願いします。</p>
   ```

3. ブラウザで確認し、commit して push する

   ```bash
   git add site/index.html
   git commit -m "開館時間の表に入館の注記を追加する"
   git push -u origin quest/05-entry-note
   ```

4. {{pr_long}} を作る (タイトル `quest-05: 開館時間の表に入館の注記を追加する`、先頭行 `クエスト: quest-05`、5 項目)。{{ci}} が緑になったら進行役にレビューを依頼する
5. 進行役から **{{request_changes}}** が返ってくる。コメントを読み、次を行う
   - 指摘のとおりに修正して commit し、push する (同じブランチに push すれば {{pr}} に反映される)
   - スレッドに「直した」と返信して {{resolve}} する。直さないなら理由を、分からなければ `[Q]` を
   - {{rerequest}} で、もう一度レビューを依頼する
6. {{approve}} が付いたら {{squash_merge}} でマージし、ローカルを掃除する

## 完了条件

{{pr}} がマージされると、ゲーム画面がこの演習を自動で済にする。

- [ ] {{request_changes}} を 1 回受けた
- [ ] 指摘に対して「直した / 直さない理由 / 質問」のどれかで返信し、{{resolve}} した
- [ ] 修正を push した後に、もう一度レビューを依頼した
- [ ] {{approve}} の後に {{squash_merge}} でマージした
- [ ] ローカルの main を pull し、作業ブランチを消した

## 参考

- [{{platform}} での操作の 1 枚](../{{platform_doc}}) の「レビューの操作」
- [レビュー観点の ID](../docs/review-ids.md)

## 詰まったら

差し戻しのコメントの意味が取れないときは、推測で直さずスレッドで `[Q]` を書く。

## 進行役メモ

差し戻しの台本 (必ず 1 回は差し戻す):

1. {{pr}} が来たら、まず **{{pr}} のコメント** で伝える: 「担当者から連絡があり、文言を『入館は閉館の 15 分前までにお願いします。』に統一します。」
2. 続けて該当行に行コメント: `[SHOULD] REQ-01 (仕様との一致) 上のコメントで伝えた文言 (閉館の 15 分前) に合わせてください。連絡が遅くなりすみません。` を書き、{{request_changes}} で返す
3. 実際に気づいた指摘があれば、ID 付きで 1 件まで足してよい (例: class 名、インデント)。ここで本題を増やしすぎない
4. 修正と返信と再依頼が来たら、返しの形 (3 分類、{{resolve}}、再依頼) を見て {{approve}}

見るところ: 修正 commit が同じブランチに push されているか、返信が「直した」の一言で終わらず何を直したか書いてあるか。
到達チェック **T-3 / H-3**。ゲーム画面で済になったら進行役は手元の記録に達成日を書く
