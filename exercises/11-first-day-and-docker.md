# quest-11: 現場の初日に聞くことを用意し、Docker で砂場を動かす

<!-- quest:start -->
## 状況

この研修で覚えた流れ (GitHub Flow、Squash and merge、5 項目の {{pr}}、承認 1 人) は **既定** であって、現場では違うかもしれません。
違いを初日に聞いて埋められるように、質問を自分の言葉で用意します。
あわせてサイドクエストとして、用意された compose で砂場のサイトを Docker で動かします。
この演習は **対面 4 (振り返り)** で締めます。{{pr}} は作らず、書くものはすべて **ゲーム画面の 11 のメモ** に書きます。
メモはブラウザに保存されるので、対面 4 は書いたときと同じ PC とブラウザで開いてください。

## やること

1. [現場の初日に聞くこと](../docs/first-day-questions.md) を読む。質問ごとに「自分ならこう聞く」を 1 行ずつ、**ゲーム画面の 11 のメモ** に書く
2. 同じ文書の「既定との差分の埋め方」の表を見て、同じメモに次を 1 行で書く: 「現場で squash が禁止だったら、自分の操作はどう変わるか」
3. サイドクエスト: Docker で砂場を表示する (Docker Desktop が WSL2 と連携している前提)

   ```bash
   docker compose up
   ```

   ブラウザで `http://localhost:8080` を開く。ひだまり図書室が表示されれば OK。同じメモに「表示できた」と 1 行書く。終わったら `Ctrl+C` で止めて

   ```bash
   docker compose down
   ```

   `compose.yaml` を開いて、何をしているかを同じメモに 2 行で書く (どのイメージを使い、どのフォルダを見せているか)

4. [到達チェック](../docs/goals.md) を自分で読み、「1 人でできる」と言える行の ID を同じメモに書く。できないと思う行もそのまま書く
5. 対面 4 で進行役と振り返る

## 完了条件

すべて満たしたら、ゲーム画面のこの演習の完了条件にチェックを付ける。この演習は {{pr}} が無いので、チェックが全部付くと済になる。

- [ ] 質問の 1 行が、文書の項目の数だけゲーム画面の 11 のメモにある
- [ ] 「squash 禁止ならどう変わるか」を 1 行で書いた
- [ ] Docker で砂場を表示でき、`compose.yaml` の説明を 2 行で書いた (Docker が入らない環境なら、その旨を書いて省略してよい)
- [ ] 到達チェックの自己評価をメモに書いた
- [ ] 対面 4 を終えた

## 参考

- [現場の初日に聞くこと](../docs/first-day-questions.md)
- [4 つの動詞](../docs/merge-methods.md)
- Dockerfile の書き方はこの研修では扱わない。現場で「compose を動かすだけか、Dockerfile を書く側か」を聞く

## 詰まったら

Docker Desktop が無い、または WSL2 と連携していないときは、進行役に相談する。入らなければ省略してよい。
