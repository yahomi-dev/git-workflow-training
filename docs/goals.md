# 到達チェック

研修を終えたときに受講者が **1 人でできる** ことの一覧。4 群 20 行。
「1 人でできる」とは、`docs/` の手順書は見てよいが、進行役の手を借りずに演習の完了条件を満たせることを指す。
各行の「確かめる演習」で達成を見る。達成日の記録は進行役が手元に持ち、このリポジトリには書かない。

## W. WSL2 と環境

| ID | 1 人でできること | 確かめる演習 |
|---|---|---|
| W-1 | WSL2 の Ubuntu を起こし、ホーム配下に作業ディレクトリを作って移動できる。リポジトリを `/mnt/c` に置かない理由を一言で言える | 02 |
| W-2 | `git config` で名前、noreply のメール、`core.autocrlf=input` を設定し、`git config --list` で確認できる | 02 |
| W-3 | `gh auth login` で GitHub に認証し、push できる状態にできる | 02 |
| W-4 | VS Code を WSL に接続してリポジトリを開き、統合ターミナルから git を使える | 02 |

## G. Git の基本操作

| ID | 1 人でできること | 確かめる演習 |
|---|---|---|
| G-1 | 変更を add / commit し、`git status` と `git log --oneline --graph` で今の状態を読める | 03 |
| G-2 | 命名規則どおりにブランチを切って push し、GitHub 上でそのブランチを確認できる | 03 |
| G-3 | 衝突マーカーを読み、両方の意図を保って解消し、コミットして push できる | 06 |
| G-4 | `git rebase main` で自分のブランチを載せ替え、`--force-with-lease` で push できる。`--force` との違いを説明できる | 07 |
| G-5 | マージ済みの変更を `git revert` (または GitHub の Revert) で打ち消す PR を作れる | 09 |
| G-6 | 複数のコミットを 1 つにまとめ (squash)、main に ff できる状態にして PR を出せる | 07 |

## T. チーム開発の流れ

| ID | 1 人でできること | 確かめる演習 |
|---|---|---|
| T-1 | Issue を読み、完了条件を自分の言葉で 1 行にして、作業前に確認できる | 04 |
| T-2 | PR を 5 項目 (意図 / 変更内容 / 影響範囲 / 確認方法 / 相談したいこと) で書き、レビューを依頼できる | 04 |
| T-3 | レビューコメントに「直した / 直さない理由 / 質問」のどれかで返し、修正を push して再依頼し、resolve できる | 05 |
| T-4 | 他人の PR を観点の ID と温度感 (MUST / SHOULD / NITS / Q) を付けて指摘し、Request changes できる | 08 |
| T-5 | Squash / Rebase / Merge commit / ff の違いを 4 つの動詞で説明し、現場の方式を聞いて合わせられる | 07 |
| T-6 | hotfix を main から切って最短で入れ、annotated tag を打って Release を作れる | 10 |
