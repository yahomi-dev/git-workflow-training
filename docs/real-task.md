# 実タスク編 (演習 12)

砂場で通した流れを、自分が実際に関わっているプロジェクトで 1 往復する。
砂場と違うのは「相手が本物」なこと。手順は同じにする。

## やること

1. **タスクを 1 つ選ぶ** (そのプロジェクトの課題管理にあるもの。Issue やチケットなど呼び方は現場で違う)。完了条件を自分の言葉で 1 行にして、作業前に担当者か進行役に確認する。1 行にできないなら大きすぎるので、分ける
2. **ブランチを切る**。そのプロジェクトの命名規則に合わせる (無ければ `<種類>/<短い説明>`)
3. **小さくコミットし、PR (GitLab では MR) を出す**。本文は 5 項目 (意図 / 変更内容 / 影響範囲 / 確認方法 / 相談したいこと)。プロジェクトにテンプレートがあればそれに従い、無い項目は本文に足す
4. **レビューを受けて 1 往復する**。コメントには「直した / 直さない理由 / 質問」のどれかで返す。マージ方式はプロジェクトの既定に合わせる (分からなければ聞く。[first-day-questions.md](first-day-questions.md))
5. **運用手順の初版を書く**。自分が抜けた後に、別の人が同じ作業をできる手順。書く場所はプロジェクトの文書の置き場。次の構成で 1 枚に収める:
   - 目的 (この手順で何ができるか)
   - 前提 (必要な権限、環境、入力)
   - 手順 (1 手順 1 コマンドか 1 操作。結果の確かめ方を添える)
   - 困ったとき (よくある失敗と見る場所)
   - 連絡先 (誰に聞くか)

## 完了条件

- PR が 1 本以上マージされている (またはレビューを受けて差し戻しに対応している)
- 運用手順の初版が、別の人に読んでもらって「これでできそう」と言われている

## 砂場との違いで気をつけること

- 衝突は NPC が起こしてくれない。push する前に `git fetch` して main との差を見る
- CI の内容はプロジェクトごとに違う。赤くなったらログの赤い行から読む
- 分からないことは 30 分で聞く。1 人で抱えない
